## 内容保护与模板

保持已有主界面身份检查，未放宽外部网页、预览或独立窗口的准入条件。新增 41 个精确内容标记及 `file-viewer-root` class token，覆盖以下已核验位置：

- 评论、上下文卡片、任务/协调智能体名称与指令。
- 语音转写、侧问题正文与包含项目名的协调智能体欢迎语。
- 文件标题、下载文件名、网页来源与提示、SSH 主机名。
- 原生文件查看器、CSV 表格正文、PDF 文本层及 Notebook 内容。
- 当前语音设置和音色选择器里的音色名称，保留 Neno 等官方名称。

保护判断先于文本及文案属性读取，首次扫描、变更、重复注入、属性兜底和 Shadow DOM 使用同一策略。独立的工具栏与设置控件仍可翻译；部分受保护卡片内的固定文字和逐词动画欢迎语会保持英文。未知组件仍须另行核验。

新增模板覆盖配额 `d/h/m` 倒计时、下载百分比、评论草稿数、MCP 服务器启动失败数、帮助项和侧问题混合计数、CSV 行数，以及终端沙箱不可用的预设列表和空输入发送下一条的快捷键。Node 回归同时验证文本和属性、单复数、重复注入，以及不合法的进度或倒计时格式。

“默认”权限标签和排队消息快捷键提示框使用精确来源识别：先检查所有保护祖先，再根据 `aria-describedby` 找到唯一活动触发控件，核对权限菜单标记或快捷键控件结构。只有这两种来源的固定文案可以翻译；权限标签里的项目名及其他未知内容不走通用词典、子串替换或漏翻计数。提示框属性和采集仍不放行。监听关联属性的迟到变更，处理提示框先挂载、触发控件后建立关联的情况；复用提示框及 Shadow DOM 同样重新判断。
